## Instructions

Extract factual claims from the narrative and verify against source data:

1. **Financial Claims**: Revenue, expenses, program ratios, executive compensation
2. **Program Claims**: Beneficiary counts, geographic reach, program descriptions
3. **Historical Claims**: Founding dates, leadership changes, milestones
4. **Impact Claims**: Outcomes, metrics, efficiency measures

For each claim:
- Find the corresponding source value
- Check if they match (allowing for rounding, formatting differences)
- Flag any significant discrepancies

## Classify every issue with `discrepancy_kind`

Say which of these you mean. Only the first two describe a fault in the
narrative; the others describe the state of our data.

- **contradiction** — the source reports a value, and it differs materially
  from the narrative's (>5% for percentages, >10% for dollar amounts).
  You must fill in both `claim_value` and `source_value`.
  Example: narrative says 82.7%, source shows 75.2%.
- **fabrication** — the narrative states a specific number for a field, and
  the SOURCE HAS NO VALUE for it at all. A number no source reported must
  never appear in donor-facing prose. Use this only when the field is
  genuinely absent or null in the source data.
- **unverifiable** — the source data does not address this claim, so you
  cannot judge it either way. This is different from fabrication: the claim
  is qualitative, or derived, or about something we simply did not collect.
  If the narrative describes something the source data has no notion of
  (e.g. a domestic/international expense split we never computed), that is
  unverifiable, NOT a contradiction and NOT a fabrication.
- **rounding** — the two values agree once rounding is allowed.

## Severity Guidelines

`severity` and `discrepancy_kind` are SEPARATE fields with separate
vocabularies. `severity` is ALWAYS exactly one of "error", "warning", "info" —
never a discrepancy_kind value. Pick severity from the kind you chose:

| discrepancy_kind | severity |
|------------------|----------|
| contradiction    | error    |
| fabrication      | error    |
| unverifiable     | warning  |
| rounding         | info     |

A minor discrepancy (1-5%) is `contradiction` with severity "warning".
Rounding examples: 75.2% vs 75.21%, $816K vs $816,038, 50.3% vs 50.29%.

If `claim_value` and `source_value` are the same number, do not report an
issue at all.

## Acceptable Tolerances (use "info" severity)
- Percentages: ±0.5 percentage points (e.g., 75.2% vs 75.7% is acceptable)
- Dollar amounts: ±$1,000 for amounts under $100K, ±1% for larger amounts
- Years/dates: Exact match required for founding year
- Working capital: ±0.5 months difference is acceptable

## CRITICAL: Working Capital Units
Working capital is measured in MONTHS, not years. If narrative says "X years" but source shows "Y months":
- This is an ERROR if the units don't match (e.g., "13.9 years" vs "14.5 months")
- Convert to same units before comparing: 13.9 years = 166.8 months ≠ 14.5 months

## CRITICAL: Do NOT Report as Errors
- Revenue/expense amounts that are simply rounded (e.g., "$816K" when source is $816,038)
- Percentage differences under 1 percentage point (75.2% vs 75.8%)
- Values that can be derived from source data using standard calculations
- A figure that matches the source for the fiscal year the narrative NAMES.
  Sources cover different years — ProPublica's latest filing often lags Charity
  Navigator by a year — so the same charity legitimately has different revenue in
  FY2023 and FY2024. Compare like-for-like on fiscal year. If the narrative says
  "FY2024 revenue was $11,142,566" and the FY2024 source says $11,142,566, that is
  CORRECT even when the FY2023 filing says $9,535,194. A different year's figure is
  not a contradiction, and neither is the narrative choosing the most recent year.
  Report an error only when the narrative's figure disagrees with the source for
  the SAME year the narrative cites.

## Special Field Semantics

**claims_zakat_eligible**: This field indicates whether the charity CLAIMS zakat eligibility on their website.
- `claims_zakat_eligible: true` → Charity claims zakat eligibility → wallet_tag should be ZAKAT-ELIGIBLE
- `claims_zakat_eligible: false` → Charity does NOT claim zakat → wallet_tag should be SADAQAH-ELIGIBLE

Do NOT report an error if:
- wallet_tag is SADAQAH-ELIGIBLE and claims_zakat_eligible is false (this is CORRECT)
- wallet_tag is ZAKAT-ELIGIBLE and claims_zakat_eligible is true (this is CORRECT)

Only report actual issues. If all facts check out, return empty issues array.
